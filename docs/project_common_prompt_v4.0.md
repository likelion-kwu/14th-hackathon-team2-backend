## 2. 서비스 한 줄 설명

**미래의 나를 표현한 AI 아바타가 사용자의 말투로 루틴을 독려하고, 사진 미션으로 피부·생활 루틴을 인증하면 획득 Point에 따라 Item이 해금되고 연속 하루 성공에 따라 Story와 아바타 외형이 변화하는 웰니스 루틴 서비스다.**

---

## 3. 해결하려는 문제

피부 관리와 생활 습관은 짧은 기간 안에 결과가 바로 나타나지 않는다.

사용자는 세안, 보습, 선크림, 물 마시기, 수면 관리 등의 행동을 실천해도 현재 행동이 미래에 어떤 변화를 만드는지 즉시 체감하기 어렵다.

처음에는 루틴을 열심히 실천하지만 다음과 같은 이유로 중단하기 쉽다.

- 변화가 바로 보이지 않는다.
- 반복적인 기록 방식이 지루하다.
- 체크 버튼만 누르면 실제로 행동하지 않아도 완료할 수 있다.
- 자신이 루틴을 이어가야 하는 이유를 잊기 쉽다.

사용자가 루틴을 지키려는 이유는 체크 표시를 채우기 위해서가 아니라 더 나은 미래의 자신이 되고 싶기 때문이다.

이 서비스는 `TO_DO`를 제외한 완료 루틴에서 수령한 Point를 Item 해금과 월간 경쟁으로 연결하고, `SKIN / WELL_BEING / HEALTH_FIT / DIET`의 연속 하루 성공 기록을 Story 해금과 아바타 외형 변화로 표현하며, 아바타가 사용자의 말투로 반응하게 하여 현재 행동과 미래의 나를 연결한다.

## 4. 주요 사용자

주요 사용자는 다음과 같다.

- 피부와 생활 루틴을 꾸준히 실천하고 싶은 20~30대
- 루틴을 시작하지만 며칠 뒤 중단하는 사용자
- 결과가 바로 보이지 않으면 동기를 잃기 쉬운 사용자
- 캐릭터 성장, 수집, 꾸미기 요소에 흥미를 느끼는 사용자
- 단순한 알림보다 자신에게 친숙한 말투의 피드백을 선호하는 사용자

서비스의 중심은 피부 루틴이지만, 다음과 같은 생활 루틴도 함께 등록할 수 있다.

- 수분 섭취
- 수면 준비
- 간단한 식사 행동
- 가벼운 운동
- 기타 사용자가 직접 정한 생활 습관

일상 전체를 관리하는 복잡한 건강관리 서비스로 범위를 확대하지 않는다.


# 6. 주요 기능

## 6.1 사용자 및 아바타 설정

MVP의 기본 진입 방식은 **일반 게스트**다. 정식 회원가입 또는 소셜 로그인은 Could다. 발표 시에는 별도 데모 모드를 만들지 않고, 일반 게스트 1개에 시연에 필요한 샘플 상태를 미리 준비해 사용한다.

일반 게스트는 사용자별 임시 식별자를 가지며 동일 브라우저에서 루틴, 아바타, 말투, 기록 상태를 이어서 사용할 수 있다. 다른 브라우저나 기기에서 계정을 복구하는 기능은 MVP에서 제공하지 않는다.

닉네임은 최초 설정에서 필수 입력한다. 카카오톡 참여자 이름과 서비스 닉네임은 별도 데이터로 관리한다.

아바타의 표현 방식은 **2D 완성 이미지 Stage 교체 + 프론트 Item PNG overlay**로 확정한다.

### 성장 트랙

온보딩에서 다음 중 하나를 선택하며 MVP에서는 변경하지 않는다.

```text
SKIN
WELL_BEING
HEALTH_FIT
DIET
```

`TO_DO`는 Avatar 성장 트랙이 아니다.

### 얼굴 사진

얼굴 사진은 선택 입력이다.

- 제공 시 얼굴 특징 참고용으로만 사용한다.
- 몸, 포즈, 체형은 고정 Template을 유지한다.
- 사진에서 피부 상태, 안색, 붓기 또는 건강 상태를 분석해 Stage를 결정하지 않는다.
- 사진이 없으면 디자이너 기본 얼굴 Template을 사용한다.
- 한 명의 얼굴, 정면 또는 정면에 가까운 사진, 얼굴이 충분히 보이는 사진을 안내 기준으로 한다.
- 서버에 업로드한 원본 얼굴 사진은 각 생성/재생성 요청 처리 후 즉시 삭제한다.

### Stage 생성

최초 설정에서 세 장을 모두 생성한다.

```text
고정 Template + 성장 트랙 + (선택) 얼굴 reference
→ Stage 1
→ Stage 1 기준 Stage 2
→ Stage 1 기준 Stage 3
```

Stage 2에서 Stage 3으로 연쇄 생성하지 않는다.

트랙별 시각 프리셋:

```text
SKIN        → 피부가 덜 정돈된 표현 → 중간 → 더 정돈된 표현
WELL_BEING  → 칙칙/피곤한 안색 → 중간 → 더 밝고 생기 있는 안색
HEALTH_FIT  → 얼굴 붓기 표현 → 중간 → 붓기가 더 빠진 얼굴선
DIET        → 얼굴 붓기 표현 → 중간 → 붓기가 더 빠진 얼굴선
```

실제 사용자 상태를 분석하거나 의료·건강 효과를 예측하는 기능이 아니다. 모든 트랙에서 체형 변화는 사용하지 않는다.

### 이미지 규격·저장

최종 Stage asset은 다음 규격을 사용한다.

```text
250×500 PNG
RGBA 투명 배경
동일 캔버스
동일 포즈
동일 신체 위치
```

- 생성된 Stage 1/2/3은 백엔드가 사용하는 가비아 서버 host disk에 저장한다.
- Docker에서는 host directory를 volume/bind mount한다.
- DB에는 이미지 binary가 아니라 현재 활성 asset set의 논리 key를 저장한다.
- Stage 2/3은 미리 생성하더라도 실제 Story 해금 전에는 사용자에게 노출하지 않는다.

### 재생성·fallback

- 온보딩에서 세트 재생성 1회를 허용한다.
- 새 Stage 1/2/3 세트가 모두 준비된 뒤에만 기존 세트를 교체한다.
- 새 세트 생성에 실패하면 기존 세트를 부분 삭제/교체하지 않는다.
- 초기 생성은 실패 시 자동 1회 재시도한다.
- 초기 생성이 다시 실패하면 성장 트랙별 기본 Stage 세트로 온보딩을 계속한다.
- 원본 사진을 서버에 보관하지 않으므로 재생성에서 같은 사진을 쓰려면 프론트가 다시 전송한다.

### Item overlay

Item은 프론트 정적 asset이다.

```text
250×500 Avatar PNG
+ 250×500 Item transparent PNG 여러 개
→ 프론트 overlay
```

- Item 여러 개 동시 장착 가능
- backend는 `UserItem.equipped`와 `assetKey`만 관리
- 좌표/bodyPart/layerOrder를 DB에 저장하지 않음
- Item 장착/해제 때문에 AI Avatar 이미지를 다시 생성하지 않음

아바타는 다음 역할을 한다.

- 메인 화면의 중심 시각 요소
- 루틴 안내 및 인증 미션 전달
- 사용자 말투를 반영한 짧은 대사 출력
- Story 해금에 따른 성장 상태 표현
- 획득한 Item의 시각적 장착

## 6.2 아바타 말투 설정

말투 설정 기능은 별도 문서인 `speech_style_system_SRS_v2.7.md`를 최우선 구현 기준으로 사용한다.

사용자는 다음 두 방식 중 하나만 선택할 수 있다.

1. 카카오톡 대화 ZIP 파일을 이용한 말투 분석
2. 준비된 프리셋을 이용한 말투 설정

두 방식은 동시에 활성화하지 않는다.

### 카카오톡 방식의 핵심 흐름

```text
카카오톡 ZIP 업로드
-> 서버 파일 검증
-> 대화 TXT 파싱
-> 참여자 목록 추출
-> 사용자가 본인 선택
-> 사용자 메시지 전처리
-> 개인정보 마스킹
-> OpenAI 말투 분석
-> 말투 프로필 JSON 생성
-> 대표 예시 선정
-> 상황별 아바타 대사 사전 생성
-> 원본 및 임시 데이터 삭제
```

### 주요 확정 조건

- 카카오톡 채팅방 ZIP 파일은 MVP에서 1개만 분석한다.
- 사용자는 참여자 목록에서 본인을 직접 선택한다.
- 선택한 사용자의 메시지만 말투 분석 대상으로 사용한다.
- 직전 상대방 메시지 1개는 문맥 이해에만 사용한다.
- 상대방의 말투는 사용자 말투에 포함하지 않는다.
- 유효 메시지가 50개 미만이면 분석하지 않는다.
- 최신 유효 메시지 최대 500개를 분석한다.
- 동일 사용자의 1분 이내 연속 메시지는 최대 5개까지 결합한다.
- 대표 예시는 최대 20개이며 각 문장은 최대 50자다.
- 말투 분석은 기본적으로 OpenAI API 2회 호출 구조를 사용한다.
- 원본 ZIP, TXT, 전체 메시지와 상대방 문맥은 분석 후 삭제한다.
- 임시 분석 데이터는 최대 10분만 보관한다.
- 비동기 분석 시작 후 프론트는 기본 **2초 간격**으로 Job 상태를 polling하며 `COMPLETED`, `FAILED`, `EXPIRED`에서 polling을 종료한다.
- 사용자의 성격, 정신 상태, 건강 상태를 진단하지 않는다.
- 사용자별 파인튜닝과 자동 재학습은 하지 않는다.

### 사용자가 수정할 수 있는 말투 항목

- 반말 또는 존댓말
- 문장 길이
- 직설성
- 다정함
- 장난기
- 욕설 사용 여부

욕설은 실제 사용자 대화에서 발견된 경우에만 사용자가 활성화할 수 있다.

욕설 기본값은 OFF다.

욕설을 활성화해도 다음 표현은 금지한다.

- 인신공격
- 능력이나 존재 비하
- 외모 비하
- 혐오 표현
- 협박
- 자해 또는 죽음 유도
- 건강 문제를 이용한 압박

### 아바타 대사 원칙

아바타는 현재 사용자의 단순 복제본이 아니라 **조금 더 성숙하고 건강한 미래의 나**다.

대사 생성 시 다음 원칙을 적용한다.

- 사용자 말투 특성 약 80%
- 미래의 나다운 안정감과 건강한 행동 유도 약 20%
- 짧은 말풍선 대사는 공백 포함 최대 50자
- 사용자 이름은 가끔만 사용
- 실제 사용자 예시를 그대로 복사하지 않음
- 사용자가 실행할 수 있는 행동을 안내
- 의료적 진단이나 효과 보장 금지

### 사전 생성 대사 상황

최소 루틴 기능은 MVP에서 사용하지 않는다.

MVP에서는 다음 8개 상황마다 대사 5개를 생성한다.

| 코드 | 의미 |
|---|---|
| `ROUTINE_UPCOMING` | 루틴 시작 전 |
| `ROUTINE_AVAILABLE` | 루틴 수행 가능 시간 진입 |
| `ROUTINE_REMINDER` | 정해진 시간 내 미완료 |
| `ROUTINE_COMPLETED` | 개별 루틴 완료 |
| `ALL_COMPLETED` | 오늘의 진행률 대상 루틴 모두 완료 (`TO_DO` 제외) |
| `STREAK_CONTINUED` | 연속 실천 기록 유지 |
| `STREAK_BROKEN` | 연속 기록 중단 |
| `RETURN_AFTER_ABSENCE` | 며칠 만에 복귀 |

사용자당 기본 사전 생성 대사는 총 40개이며 **8개 상황 모두 MVP Must**다.

사용자의 말투 세부 설정 수정과 욕설 사용 설정도 MVP Must다. 사용자가 말투 설정을 수정하면 기존 사전 생성 대사 40개를 삭제하고 새 설정에 맞게 전부 다시 생성한다.

### 말투 초기화

사용자는 현재 말투를 초기화할 수 있다. 카카오톡 기반과 프리셋 기반 모두 동일한 초기화 정책을 적용한다.

초기화 시 다음 말투 관련 데이터를 모두 삭제한다.

- 활성 말투 방식 및 프리셋 선택값
- 말투 프로필 JSON
- 사용자 수정값
- 대표 예시
- 사전 생성 대사 40개 및 사용 이력
- 욕설 관련 설정과 말투 분석 메타데이터

닉네임, Avatar 성장 트랙·Stage asset set·재생성 상태, 루틴, Point 수령, 누적 하루 성공 기록, 연속 하루 성공 기록, 획득 Item, Story 해금, 인증 기록 등 말투와 무관한 데이터는 유지한다. 초기화 후에는 말투 설정 화면으로 이동하며, 카카오톡 또는 프리셋 중 하나를 다시 설정하기 전까지 홈에 진입할 수 없다.

프리셋을 새로 선택하면 기존 카카오톡 기반 데이터가 삭제되고 프리셋 기반 사전 대사 40개를 생성한다. 카카오톡 방식으로 전환하면 기존 프리셋 선택값과 프리셋 기반 대사를 제거한 뒤 새 분석 결과로 대사 40개를 생성한다.

## 6.3 루틴 생성·수정·삭제

루틴 관리를 위한 별도의 전체 페이지는 만들지 않는다. 루틴 생성·수정·삭제는 메인 화면의 루틴 팝업에서 수행한다.

### 카테고리

```text
SKIN
WELL_BEING
HEALTH_FIT
DIET
TO_DO
```

`SKIN / WELL_BEING / HEALTH_FIT / DIET`는 `DAILY` 또는 `DAYS_OF_WEEK` 반복 루틴이고, `TO_DO`는 특정 날짜의 `ONCE` 일회성 보조 작업이다. `TO_DO`는 DailyRoutine 생성과 PHOTO/CHECK 인증은 가능하지만 오늘 진행률, DailySuccess, Story streak, Point Claim, Item 해금, Competition Point에서는 제외한다.

### 카테고리별 추천

MVP 추천은 실시간 AI 생성이 아니라 서버 코드/JSON/YAML의 **사전 검수 추천 Pool**에서 해당 카테고리 후보 3개를 내려주는 방식이다. 추천 선택 시 기존 생성 폼의 내용과 권장 인증 물건을 채우고 사용자가 시간·날짜/요일·인증 물건을 최종 결정한다. OpenAI 실시간 추천은 MVP 제외다.

### 생성 입력

반복 루틴:
- category
- content
- startTime / endTime
- `DAILY` 또는 `DAYS_OF_WEEK`
- daysOfWeek(필요 시)
- verificationObject

TO_DO:
- category=`TO_DO`
- content
- scheduledDate
- startTime / endTime
- repeatType=`ONCE`
- verificationObject

### 날짜·시간 및 집합 고정

- 자정 넘김 금지, `startTime < endTime`, `24:00` 미지원, 최대 `23:59`
- PHOTO/CHECK는 설정된 수행 시간 안에서만 가능
- 인증 시간은 서버 시각 기준
- 이미 시작 시간이 지난 루틴은 수정/삭제로 당일 수행 대상을 소급 변경하지 않음
- 같은 serviceDate에서 첫 성공 Verification 발생 후 해당 날짜 DailyRoutine 집합 고정
- 이미 확정된 Verification, PointClaim, DailySuccess, ItemUnlock, StoryUnlock을 이후 Routine 수정/삭제로 취소하지 않음
- `TO_DO` 완료에는 Verification만 저장하며 PointClaim/DailySuccess/Story/Item/Competition 계산에는 사용하지 않음

### 루틴 관련 제외

- 최소 루틴
- 복잡한 하위 카테고리
- 제품별 상세 데이터
- 루틴 단계별 하위 항목
- AI가 사용자 승인 없이 루틴 자동 변경
- 별도 루틴 관리 탭

## 6.4 메인 화면

메인 화면은 사용자가 서비스에 들어왔을 때 가장 먼저 보는 핵심 화면이다.

메인 화면은 제공된 스케치를 기준으로 설계한다.

### 화면 중심 요소

- 미래 아바타
- 오늘의 루틴 진행률 게이지
- 하단 내비게이션

불필요하게 많은 카드나 통계를 배치하지 않고 아바타에 집중할 수 있도록 구성한다.

### 아바타 상호작용

사용자가 아바타를 누르면 말풍선 또는 대사 영역이 나타난다.

아바타는 현재 상황과 말투 프로필에 따라 짧은 대사를 출력한다.

루틴 인증 완료처럼 서버가 이미 상황을 판정할 수 있는 기능은 완료 후 프론트가 별도 대사 API를 다시 호출하지 않도록 **도메인 API 응답에 선택된 대사를 함께 내려준다.**

```text
인증 성공 + 일부 루틴 남음
→ ROUTINE_COMPLETED

인증 성공 + 오늘의 진행률 대상 루틴 전체 완료 (`TO_DO` 제외)
→ ALL_COMPLETED
```

아바타 직접 클릭처럼 사용자의 명시적 새 대사 요청은 별도 대사 선택 API를 사용할 수 있다.

예시는 다음과 같다.

- “왔냐?”
- “아직 안 한 거 있지?”
- “오늘도 하나씩 해보자.”

### 진행률 게이지

게이지는 오늘 완료한 루틴 비율을 보여준다.

예:

```text
오늘은? 67%
```

사용자가 게이지를 누르면 루틴 팝업이 열린다.

루틴 팝업에는 오늘의 루틴이 시간순으로 펼쳐진다.

각 항목 옆의 `인증` 버튼을 누르면 해당 루틴의 인증 흐름으로 이동한다.


### 하단 내비게이션

현재 스케치 기준 주요 탭은 다음과 같다.

- 기록 분석
- 홈
- 도감

추가 탭이 필요한지는 추후 결정하며, 별도 루틴 관리 탭은 만들지 않는다.

## 6.5 사진 인증 미션

사진 인증은 기본 인증 방식이다.

인증 화면에 진입하면 아바타가 오늘의 사진 미션을 알려준다.

예시는 다음과 같다.

- 제품과 함께 브이하기
- 컵과 함께 엄지척하기
- 손으로 전화기 모양 만들기
- 제품 옆에 손가락 세 개 보이기
- 물건 두 개를 지정된 위치에 놓기

### MVP 기본 방식

MVP에서는 사진 미션 문구를 사전에 여러 개 만들어 데이터로 저장하고 순환해서 사용한다.

같은 미션이 연속으로 반복되지 않도록 선택한다.

미션은 다음 기준을 만족해야 한다.

- 짧고 이해하기 쉬움
- 한 손으로 수행 가능
- 얼굴 전체 촬영을 필수로 하지 않음
- 루틴 수행을 방해하지 않음
- 위험한 동작을 요구하지 않음

### AI 미션 생성

일일 사진 미션을 OpenAI API로 생성하는 비용과 응답 시간이 충분히 낮다면 AI의 역할에 포함할 수 있다.

다만 AI 생성이 실패해도 서비스가 동작해야 한다.

따라서 구현 우선순위는 다음과 같다.

1. 사전 생성된 미션 풀에서 선택
2. AI 생성 기능이 안정적인 경우 새로운 미션 추가
3. AI 호출 실패 시 기존 미션 풀로 대체

AI가 매번 실시간 생성하는 기능은 Must가 아니다.

## 6.6 사진 인증

사용자는 인증 화면에서 사진을 촬영한다.

가능하면 갤러리의 기존 사진을 선택하는 방식보다 서비스 내부 카메라로 즉시 촬영하는 방식을 기본으로 한다.

AI 또는 이미지 분석 기능은 다음 항목만 간단히 확인한다.

- 오늘 요청한 제품이나 물건이 포함되었는가
- 오늘 요청한 손동작이나 배치가 포함되었는가
- 사진이 판정 가능한 품질인가

다음 기능은 구현하지 않는다.

- 이전 인증 사진과의 유사도 비교
- 정교한 위변조 탐지
- 사용자가 실제로 제품을 사용했는지 완벽하게 증명
- 얼굴이나 피부 상태 분석
- 피부 질환 진단

인증 결과가 불확실하면 **루틴 종료 시각 전인 경우에만** 다음 선택지를 제공한다.

- 다시 촬영
- 체크 인증으로 전환

종료 시각이 지난 뒤에는 두 선택지를 제공하지 않고 해당 루틴을 실패로 처리한다.

사진 인증은 감시 시스템이 아니라 사용자가 실제 행동한 순간을 재미있게 기록하도록 돕는 기능이다.

## 6.7 체크 인증

사진을 촬영하기 어려운 경우 사용자는 체크 인증으로 전환할 수 있다.

체크 인증을 선택하면 아바타가 사용자의 말투에 맞는 확인 대사를 보여준다.

예시는 다음과 같다.

- “진짜 한 거 맞지?”
- “침대에 누워서 누르는 건 아니지?”
- “오늘은 믿어줄게.”

사진 인증과 체크 인증은 모두 개별 루틴 완료로 인정한다.

- 두 방식 모두 해당 루틴의 수행 시간 안에서만 성공 인증할 수 있다.
- 종료 시간이 지난 미인증 루틴은 실패이며 이후 인증할 수 없다.
- 한 루틴은 사진 또는 체크 중 하나의 방식으로만 완료 처리한다.
- `SKIN / WELL_BEING / HEALTH_FIT / DIET`에서는 두 방식 모두 오늘 진행률과 하루 전체 루틴 성공 판정에 동일하게 반영한다.
- `TO_DO`에서는 PHOTO/CHECK 모두 완료·인증 기록만 남기고 진행률과 하루 성공 판정에는 반영하지 않는다.
- 인증 성공 자체에서는 Point를 지급하지 않는다.
- `TO_DO`를 제외한 완료 루틴을 같은 `serviceDate` 안에서 눌러 Point를 직접 수령한다.
- Point 대상 루틴은 PHOTO 10P / CHECK 5P이며 `TO_DO`는 0P가 아니라 **Point Claim 비대상**이다.
- 한 serviceDate에서 최대 3개 완료 루틴만 Point 수령 가능.
- 날짜가 바뀌면 미수령 Point는 소멸.
- 경험치/XP는 사용하지 않으며 Point는 MVP에서 소비/차감하지 않는다.

사진 인증 여부가 실제 피부 점수나 건강 점수에 영향을 주는 것처럼 표현하지 않는다.

## 6.8 아이템 해금, 스토리 및 아바타 외형

`SKIN / WELL_BEING / HEALTH_FIT / DIET` 개별 루틴 인증은 오늘 진행률과 하루 전체 성공 판정에 반영한다. `TO_DO` 인증은 완료 기록만 남기며 진행률·하루 성공·Point에 영향을 주지 않는다. Point 수령과 하루 성공은 별도 사건이다.

### Point 수령

```text
PHOTO 완료 루틴 → 10P
CHECK 완료 루틴 → 5P
```

- 인증 성공 즉시 자동 지급 X
- `TO_DO`는 Point Claim 비대상
- 그 외 완료 루틴을 눌러 수령
- 당일만 수령 가능
- serviceDate당 최대 3개
- 동일 DailyRoutine 중복 수령 금지
- Point 소비/차감 없음

### Point 기반 Item 해금

누적 획득 Point 100P마다 아직 보유하지 않은 활성 Item 중 1개를 랜덤 해금한다. Point는 차감하지 않는다. 기존 누적 하루 전체 성공일 `1/3/5/10/20/30/40/50` Item milestone 정책은 폐기한다.

### 하루 전체 성공과 Story

하루 전체 성공은 `SKIN / WELL_BEING / HEALTH_FIT / DIET` DailyRoutine만 대상으로 판정한다. `TO_DO`만 있는 날은 성공일로 세지 않고 streak도 끊지 않는다. 연속 성공 10/20/30/40/50회에서 EP.1~EP.5를 영구 해금하며 Stage는 1→2→3으로 진행하고 EP.3~EP.5에서 Stage 3을 유지한다. 누적 하루 성공일은 기록 지표로 유지하지만 Item 해금에 사용하지 않는다.

### 경쟁하기

- `Asia/Seoul` 기준 한 달 동안 실제 수령한 Point 합계로 순위 계산 (`TO_DO`는 Point Claim 비대상이므로 제외)
- Point 소비 기능 없음
- 월 변경 시 새 달 합계로 다시 계산하고 누적 Point/Item 해금 이력은 유지
- 동점 공동 순위(`1,2,2,4`)
- 별도 Battle Pass 없음

## 6.9 기록 분석

기록 분석 화면에서는 사용자의 루틴 수행 이력을 보여준다.

MVP에서 확인할 수 있는 정보는 다음과 같다.

- 날짜별 루틴 완료 여부
- 월간 캘린더 (Should, 일정이 부족하면 제외)
- 오늘 또는 기간별 루틴 수행률
- 루틴별 완료율
- 사진 인증 횟수
- 체크 인증 횟수
- 누적 하루 전체 루틴 성공 횟수
- 연속 하루 전체 루틴 성공 기록
- 누적 획득 Point
- 월간 획득 Point 및 경쟁 순위
- 실패 후 복귀 기록

- 최소 루틴 수행 횟수

# 11. 사진 및 개인정보 처리 원칙

## 카카오톡 데이터

말투 분석용 카카오톡 원본은 분석 완료 후 삭제한다.

장기 저장 대상은 다음으로 제한한다.

- 활성 말투 방식
- 말투 프로필 JSON
- 사용자 말투 조절값
- 대표 예시 최대 20개와 카테고리·출처
- 상황별 사전 생성 대사 40개와 필요한 사용 이력
- 욕설 ON/OFF 값
- 분석에 사용된 유효 메시지 개수
- 말투 설정 생성·수정 시각 등 필요한 메타데이터

## 루틴 인증 사진

인증 사진은 다음 처리에만 일시적으로 사용한다.

- 오늘의 미션 충족 여부 판정
- 루틴 인증 완료 처리
- 하루 전체 루틴 성공 여부와 누적·연속 성공 기록 반영
- 아이템·스토리 해금 상태 및 스토리 연동 아바타 외형 반영

인증 판정이 끝나면 사진 원본은 즉시 삭제하며 장기 저장하지 않는다.

사진 원본을 도감, 기록 분석, 사용자 갤러리 등에 보관하지 않는다.

## 아바타 생성용 사진과 Stage asset

사용자 얼굴 사진은 선택적으로 Avatar 생성에 사용한다. 얼굴 특징 reference로만 사용하고 실제 피부·안색·붓기 또는 건강 상태를 분석하지 않는다.

- 원본 얼굴 사진은 각 생성/재생성 요청 종료 시 즉시 삭제한다.
- 원본 얼굴 사진을 재생성을 위해 서버에 남겨두지 않는다.
- 생성된 Stage 1/2/3 PNG는 서비스 표시를 위해 가비아 서버 host disk에 장기 저장한다.
- 생성된 Avatar는 실제 미래 외모나 건강 개선 결과를 의미하지 않는다.

## API 키

OpenAI API 키와 기타 비밀값은 서버 환경 변수로만 관리한다.

다음 위치에 포함하지 않는다.

- 프론트엔드 코드
- Git 저장소
- API 응답
- 일반 로그
- 발표 자료

# 12. API 및 데이터 설계 원칙

API 명세서를 작성할 때는 다음 흐름을 중심으로 설계한다.

```text
사용자
-> 아바타
-> 말투 설정
-> 루틴 CRUD
-> 오늘의 루틴 조회
-> 미션 조회
-> 사진 또는 체크 인증
-> `TO_DO`는 완료 기록만 저장하고 성장/보상 계산에서 제외
-> 그 외 카테고리의 하루 전체 루틴 성공 판정 및 누적·연속 성공 기록 처리
-> Point Claim 기반 아이템 해금 / Story 해금 및 스토리 단계에 따른 아바타 외형 반영
-> 기록 조회
```

각 API에는 다음을 명확히 작성한다.

- 목적
- HTTP 메서드
- URL
- 인증 필요 여부
- 요청 헤더
- Path Parameter
- Query Parameter
- Request Body
- 성공 응답
- 실패 응답
- 오류 코드
- 입력값 검증
- 관련 데이터 변경
- 이미지 또는 임시 데이터 삭제 시점
- 중복 요청 처리
- 인증 시간창 검증 (`ROUTINE_NOT_STARTED`, `ROUTINE_WINDOW_CLOSED` 등)
- 권한 검증
- 테스트 조건

사진 업로드 API는 사진 파일을 영속 저장한다는 가정으로 설계하지 않는다.

사진은 임시 파일 또는 메모리 기반 처리 후 판정이 끝나면 삭제한다.

루틴 CRUD API는 확정된 5개 카테고리와 반복 타입을 명시한다.

```json
{
  "category": "SKIN",
  "content": "선크림 바르기",
  "startTime": "07:00",
  "endTime": "09:00",
  "repeatType": "DAYS_OF_WEEK",
  "daysOfWeek": ["MON", "WED", "FRI"],
  "verificationObject": "COSMETIC_CONTAINER"
}
```

# 13. 개발 작업 시 지켜야 할 원칙

4. 수정하거나 생성할 파일
5. 데이터 흐름
6. API 입출력
7. 예외 상황
8. 위험 요소
9. 테스트 계획
10. 8월 21일 일정에 미치는 영향

Codex CLI는 관련 코드를 먼저 검색하고 현재 프로젝트 패턴을 따라야 한다.

한 번에 프로젝트 전체를 구현하도록 요청하지 않는다.

작업은 다음과 같이 작은 단위로 분리한다.

- 데이터 모델
- API
- 서비스 로직
- OpenAI 연동
- 사진 인증
- 프론트엔드 화면
- 오류 처리
- 테스트
- 배포 설정

구현 후에는 다음을 확인한다.

- 빌드가 성공하는가
- 테스트가 통과하는가
- 기존 기능이 깨지지 않았는가
- 입력값 검증이 있는가
- 권한 검증이 있는가
- 오류 상황이 처리되는가
- 원본 파일이 정책대로 삭제되는가
- 로그에 카카오톡 원문과 사진이 남지 않는가
- 비밀키가 포함되지 않았는가
- 불필요한 파일이 변경되지 않았는가
- 하드코딩된 임시 데이터가 남아 있지 않은가
- Git 커밋이 가능한 상태인가

삭제, 데이터베이스 초기화, 배포 환경 변경, 인프라 변경, 비밀키 관련 작업은 사용자 확인 없이 실행하지 않는다.

- 확정된 내용과 제안을 구분한다.
- 현재 미정인 사항을 임의로 확정하지 않는다.
- 새로운 기능은 Must, Should, Could 중 어디에 속하는지 표시한다.
- 예상 구현 시간과 선행 작업을 함께 설명한다.
- 8월 21일까지 구현 가능한지 판단한다.
- 핵심 사용자 흐름과 직접 관계없는 기능은 후순위로 둔다.
- 복잡한 기능은 단순한 대안을 함께 제시한다.
- 의료 효과나 AI 정확도를 근거 없이 만들어내지 않는다.
- 피부 진단 또는 치료 서비스처럼 표현하지 않는다.
- API와 데이터 구조는 과도한 확장성보다 MVP 완성도를 우선한다.
- 기존 요구사항과 충돌하는 제안은 충돌 지점을 먼저 설명한다.
- 말투 기능을 다룰 때는 별도 SRS를 먼저 확인한다.
- 최소 루틴 기능을 다시 추가하지 않는다.
- 별도 루틴 관리 페이지를 다시 제안하지 않는다.
- 이전 인증 사진 유사도 비교를 다시 추가하지 않는다.
- 피부 반응 기록과 분석을 다시 추가하지 않는다.
- 경험치 / XP 기반 성장 시스템을 다시 추가하지 않는다.
- Item 해금 기준을 누적 하루 성공일이나 개별 루틴 완료 횟수로 되돌리지 않는다. 누적 획득 Point 100P 단위를 사용한다.

# 15. 현재 미확정 사항

다음 항목은 아직 확정되지 않았다.

- 사진 인증에 사용할 구체적인 AI 모델
- Avatar 이미지 생성/편집에 사용할 구체적인 AI 모델
- 알림 구현 여부와 방식
- 배포 세부 설정
- 아바타 설정 화면의 정확한 전환/로딩 연출
- 해금 Item과 Story를 보여줄 화면의 세부 연출
- 잠긴 Episode의 제목·썸네일·요구 일수·현재 진행도 노출 범위
- 루틴 삭제 시 확인 팝업 제공 여부
- Item pool이 모두 소진된 뒤 추가 100P milestone을 어떻게 처리할지에 대한 장기 운영 정책
